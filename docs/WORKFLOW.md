## 一、核心规则

### 1.1 Issue-Based 沟通原则

**每个对话 = 一个独立的Issue**

| 规则 | 说明 |
|------|------|
| 不在同issue评论区连续回复 | 每次交流创建新issue |
| 完成后标记done | 任务完结要更新状态 |
| 有问题创建新issue | 不要在同一issue下追问 |
| 沟通记录备份到docs/ | 所有issue沟通历史存档 |

### 1.2 正确的工作方式

```
❌ 错误方式:
W酱: SQU-14发评论问进度
C酱: 在SQU-14评论区回复
W酱: 在SQU-14评论区继续追问
C酱: 在SQU-14评论区继续回复
... (无限回复链)

✅ 正确方式:
W酱: 创建SQU-14发任务给C酱
C酱: 领取SQU-14 → 完成 → 标记done
C酱: 如有问题 → 创建SQU-17描述问题 → 发给W酱
W酱: 收到SQU-17 → 解决 → 标记done
```

---

## 二、Issue 状态流转

```
新建 → 进行中 → done
          ↓
       blocked (如有阻塞)
          ↓
       unblocked → 进行中
```

### 状态定义
- **todo**: 刚创建或领取，尚未开始
- **进行中**: 正在开发/测试
- **done**: 已完成
- **blocked**: 被阻塞，需要其他任务先完成

## 三、报告机制

### 3.1 C酱 必须做的

| 触发事件 | 动作 |
|----------|------|
| 领取任务 | 创建独立issue确认，开始开发 |
| 完成功能 | 标记原issue为done，创建新issue报告 |
| 遇到问题 | 创建新issue描述问题，发给W酱 |
| 需要帮助 | 创建新issue，描述阻塞原因 |

### 3.2 R酱 必须做的

| 触发事件 | 动作 |
|----------|------|
| 领取测试任务 | 创建独立issue确认，开始测试 |
| 完成测试 | 标记原issue为done，创建新issue报告 |
| 发现Bug | 创建新issue描述Bug，发给C酱 |
| 所有测试通过 | 创建新issue报告，发给W酱 |

### 3.3 W酱 必须做的

| 触发事件 | 动作 |
|----------|------|
| 收到C酱问题issue | 处理并回复，标记done |
| 收到R酱报告issue | Review并决策，标记done |
| 需要推进 | 创建新issue发给对应Agent |

## 五、Issue 命名规范

**格式:** `{类型}-{简短描述}`

| 类型 | 示例 |
|------|------|
| 功能开发 | `feat:照片上传功能` |
