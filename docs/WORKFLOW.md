# Agent 协作工作流程 (v2.0)

**版本:** 2.0  
**更新日期:** 2026-04-26  
**原因:** 之前的协作方式失败，C酱和R酱没有回馈，需要更清晰的工作流程

---

## 一、问题分析

### 1.1 之前失败的原因
- C酱和R酱收到Issue后没有任何动作
- 没有向W酱报告进度或完成情况
- 没有更新自己的文档
- 没有形成「规划→执行→测试」的循环

### 1.2 改进方案
1. **每次动作后必须更新文档并报告**
2. **W酱主动推动工作循环**
3. **清晰的Issue状态流转**

---

## 二、工作循环

```
┌─────────────────────────────────────────────────────────┐
│                    W酱: 规划 Issue                       │
│                         ↓                                │
│              C酱: 领取 → 开发 → 报告完成                   │
│                         ↓                                │
│              R酱: 领取 → 测试 → 报告结果                   │
│                         ↓                                │
│   W酱: Review结果 → 有Bug? → 发新Issue → 循环            │
│                         ↓                                │
│              没Bug → 标记完成 → 下一个功能                  │
└─────────────────────────────────────────────────────────┘
```

---

## 三、强制报告机制

### 3.1 C酱 必须做的事件

| 阶段 | 动作 | 文档更新 |
|------|------|----------|
| 开始开发 | 领取Issue后 | `agent-c-implementation.md` 标记"开发中" |
| 完成一个功能 | 功能开发完成 | 更新该功能的"状态"和"实现细节" |
| 遇到问题 | 无法解决时 | 在Issue下评论说明 + 更新文档 |
| 全部完成 | 所有功能开发完 | 更新状态 + 在Issue下评论通知W酱 |

### 3.2 R酱 必须做的事件

| 阶段 | 动作 | 文档更新 |
|------|------|----------|
| 开始测试 | 领取Issue后 | `agent-r-testing.md` 标记"测试中" |
| 发现Bug | 测试中发现问题 | 创建新Issue描述Bug + 更新文档 |
| 完成测试 | 所有用例测试完 | 更新状态 + 在Issue下评论通知W酱 |

### 3.3 W酱 的推动职责

- 检查C酱和R酱的进度
- 发现停滞时主动发消息催促
- Review测试报告决定下一步
