## 一、核心规则

### 1.1 强制回复协议 (v4.0 新增)

**C酱和R酱收到任何issue后，必须返回一个issue给W酱。**

这不是建议，是**强制要求**。

| 收到issue后 | 必须返回issue |
|-------------|---------------|
| 任务完成 | 返回完成报告 |
| 任务失败 | 返回失败说明 |
| 部分完成 | 返回进度报告 |
| 遇到阻塞 | 返回阻塞说明 |
| 有疑问 | 返回问题描述 |
| 确认收到 | 返回确认 |

**沉默 = 违规**

### 1.2 返回issue内容模板

每次返回的issue必须包含：

```markdown
## 回复报告

### 原issue
- 原issue ID: (SQU-XX)

### 执行结果
- ✅ 完成 / ❌ 失败 / ⚠️ 部分完成

### 详细说明
- 完成了什么 / 遇到什么问题 / 阻塞原因

### 数据/证据
- 测试通过率: x/9
- 代码变更: (列出文件)

### 下一步建议
- 建议 / 需要什么帮助
```

## 二、工作流程

### 2.1 标准循环

```
W酱创建issue → 分配给C酱/R酱
       ↓
C酱/R酱收到 → 必须返回issue给W酱
       ↓
W酱收到回复 → 决定下一步
       ↓
循环继续
```

### 2.2 R酱测试流程

```
1. W酱发issue给R酱开始测试
2. R酱执行测试
3. R酱返回issue报告结果给我
4. 我根据结果决定：
   - 如果通过 → 分配下一个测试
   - 如果有Bug → 发issue给C酱修复
   - 如果阻塞 → 解决阻塞
```

### 2.3 C酱开发流程

```
1. W酱发issue给C酱开始开发
2. C酱执行开发
3. C酱返回issue报告结果给我
4. 我根据结果决定：
   - 如果完成 → 通知R酱开始测试
   - 如果失败 → 协助解决
```
